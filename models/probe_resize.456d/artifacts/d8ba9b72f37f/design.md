# probe_resize - 装配设计文档

> 本包由 `models/shaft_support.456d` **整目录复制**而来（含提交历史），只做一件事：
> **换型**——把轴承从 `6204` 换成 `6305`，并把所有相关声明一起改到位。
> 原包 `shaft_support.456d` 未做任何修改。

## 装配目标

一根由单个深沟球轴承支撑的轴，**用来演示 P2 的接口图判定**：装配关系在
`manifest.json` 与 `ports.py` 里声明，`cad mates` 在**不生成任何几何**的前提下判定
它们是否配套。

本包的重点不是这根轴能不能用，而是**检查发生的时机**。编译器先做 IR 类型检查、再生成
代码；如果判定必须先建出几何，那这道检查就只能发生在它本该守住的那一步之后。

## 坐标与接口

- 世界坐标：X 长、Y 宽、Z 高；轴沿 +Z。
- 标准件按 cadparts 命名接口定位，不从 STEP 或图片猜接口。
- 轴承装在轴颈接口 `shaft.seat_support_a` 的 frame 原点上（`main.py` 里用
  `Pos(*seat["frame"]["origin_mm"])`），坐标来自声明而非反推。

|---|---|---:|---|---|

| 量 | 6204 | 6305 | 影响的声明 |

## 声明在哪

| 内容 | 文件 | 为什么在这 |
|---|---|---|
| 依赖与配对关系 | `manifest.json` 的 `deps` / `mates` | 纯 JSON，**读取不需要执行任何脚本** |
| 自建件的接口 | `ports.py` 的 `PORTS` | 契约与实现分家，检查才能先于几何 |
| 几何实现 | `src/main.py` | 从 `ports.py` 读契约，不重新声明尺寸 |

## 装配校验

`cad mates`（**不建几何，可先于建模运行**）：

```
cad mates
```

四条实测结论（全部在本包 6305 基线上重跑过）：

| 场景 | 判决 |
|---|---|
| 轴按 6305 定尺寸，装 6305 轴承 | `PASS` |
| `manifest` 换成 6206（孔径 ⌀30），`ports.py` 仍按 6305（轴径 ⌀25） | `WARN` — 公称尺寸不符，可能选错件 |
| `ports.py` 按 6206（轴径 ⌀30），装 6305 轴承（孔径 ⌀25） | `FAIL` — 轴径 ⌀30 > 孔径 ⌀25，装不进去 |
| `manifest` 换成 6205，`ports.py` 仍按 6305 | `PASS` — **查不出来**：两者轴孔同为 ⌀25，漂移只在 D/B 上 |

第二行是**漂移检测**：两处声明本应一致而不再一致时会被抓住。

第四行是同一个机制**抓不住的漏**：mate 只比较被引用的那一对接口（`shaft_bore` 的
直径），孔一样大就判 `PASS`，于是「manifest 声称 6205、实际建的是 6305」这种
声明与实现不一致可以整包通过 `cad mates`。D/B 差异要等几何出来才看得见。
同一道理，`ASSEMBLY_VOLUME` 这类**实测常量**也不在 `cad mates` 的视野里——
实测：把 `ports.py`/`manifest.json` 都留在 6305、只把 `ASSEMBLY_VOLUME` 留成
`24289.22`，`cad mates` 照样 `PASS`，只有 `cad run` 的 checkpoint 会报
`Volume: expected 24289.22±1.0, got 51324.20`。

其他校验：

- [x] `result` 为保留独立实体的 Compound（`expect_solids(2)` 通过）
- [ ] `expect_bbox_size` 未加——本包是接口判定的演示，不追总体包络
- [x] `cad run` / `cad mates` 均通过（6305 版：体积 51324.20 mm³、包络 ⌀62×17）

## 明确不做

- **跨包依赖（`pkg:`）未实现**：引用其它 `.456d` 包的接口解析尚未落地，`cad mates`
  遇到 `pkg:` 会跳过并给出 warning，不会假装验过。
- 配合公差与 ISO 286 配合带不在判定范围；`WARN` 那一档存在的理由正是这里说不清——
  孔径大于轴径既可能是间隙配合，也可能是选错件，仅凭声明无法判定，所以报出来而不是
  默认接受。
- 强度、寿命、热、振动、装配可达性均未验，`cad mates` 的 `boundary` 字段会明说。
- **mate 只比较被引用的那一对接口**：`shaft_bore` 直径相同即判 `PASS`，同一型号的
  外径、宽度差异，以及 `main.py` 里的实测常量，都不在判定范围内（见上表第四行）。

## 断言变更留痕（P1）

每次 `cad commit` 会把脚本的断言集合与上一版做差量，记进提交元数据并显示在
`commit_success` 事件里。**只记录，不阻止**——断言是写模型的人自己的东西，拦着不让
改既是家长式，也会在约束本身写错时把人堵死。

要防的不是「删掉」，而是**悄悄放宽**。所以记的是 diff 而不是「有变更」这个标记：

本包在 `shaft_support` 的三次提交之上再走了一次换型（`cad log` 可查回）：

| 提交 | 内容 | 记录 |
|---|---|---|
| `7d63fcd05244` | 首次提交 | 断言集合首次记录，共 2 条 |
| `1ddfcbe4f289` | 把 `VOLUME_TOLERANCE` 从 `1.0` 放宽到 `1000.0` | 移除 `expect_volume(24289.22, tolerance=1.0)`，新增 `…tolerance=1000.0` |
| `66b960eddad1` | 收回 `1.0` | 反向记录 |
| `bf9cdd2dacbf` | 换型 6204 → 6305，`ASSEMBLY_VOLUME` 随实测改为 `51324.20` | 移除 `expect_volume(24289.22, tolerance=1.0)`，新增 `expect_volume(51324.2, tolerance=1.0)` |

最后一行值得注意：换型时**没有任何人「删断言」**，只是把一个实测常量改成了新实测值，
机制照样如实记下了「上一版断言的体积约束不再成立」。反过来说，若换型时忘了改这个常量，
记录里**什么都不会出现**——它只在 `cad run` 的 checkpoint 上炸（见上文实测），
而 `cad mates` 一路 `PASS`。

注意第二行：脚本里写的是**变量名** `VOLUME_TOLERANCE`，而「参数放顶部、禁止 magic
numbers」正是本仓的约定。若只按字面提取，改顶部常量会导致断言文本一字不变、放宽完全
不可见——所以提取会先做一次**模块级字面量常量折叠**。

断言集合未变化时不记录，避免每条提交都带噪音。这条机制**不判定断言本身对不对**：
约束写错时它照样只如实记录。
