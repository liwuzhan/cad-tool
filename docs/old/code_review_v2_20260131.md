# v2.0 代码评审报告（意见稿）

## 1. 评审范围

评审对象为已提交的 v2.0 代码改动与实现总结，聚焦以下模块：
*   模型包管理（package）
*   工件管理（artifacts）
*   执行器与工作流（runtime）
*   渲染输出（feedback）
*   版本控制（vcs）
*   CLI v2 入口

## 2. 主要结论

*   **结构性重构已完成**：模型包（.456d）、JSONL 历史、STEP 工件、渲染元数据和 CLI v2 均已落地。
*   **与总结报告存在关键不一致**：`build` 不生成工件、分支指针更新无效、`releases_only` 清理策略未实现、回滚描述与实现不符。
*   **运行时隔离仍未解决**：Windows 下超时无法真正中断 `exec`，属于稳定性风险。

## 3. 事实核对与一致性

### 3.1 已落地且与报告一致

*   **模型包结构**：manifest/src/vcs/artifacts/runlog 目录体系已实现。
*   **STEP 工件**：已替代 pickle 缓存，提供 `save_step`/`load_step`。
*   **JSON 元数据**：渲染输出 PNG + JSON 元数据。
*   **JSONL 历史**：单文件追加写入提交历史。
*   **CLI v2 命令集**：init/run/build/commit/log/status/checkout/validate/render/export/artifacts 已实现。

### 3.2 报告与实现不一致

1.  **`build` 不生成工件**  
    *   报告称“build 执行全流程”，实际 `commit_message is None` 时直接返回，未保存 STEP/缩略图/指标。  
    *   结论：实现与说明不符，应修正描述或实现。

2.  **分支指针更新失效**  
    *   `update_manifest` 不支持 `branches.main` 这种 dot key，导致分支指针不会更新。  
    *   影响：`latest_per_branch` 策略将失真。

3.  **`releases_only` 清理策略未实现**  
    *   CLI 仅保留注释占位，`keep_commits` 为空时会删除全部工件。  
    *   影响：误删风险。

4.  **回滚与事务描述不符**  
    *   报告描述“错误处理和回滚”，但实现中无任何回滚机制。  
    *   影响：工件可能部分生成，状态不一致。

5.  **测试通过与覆盖率声明未验证**  
    *   测试用例数量符合描述，但缺少自动化输出或覆盖率产物支撑“100% 通过/覆盖率”结论。

## 4. 风险与优先级建议

### P0
*   **脚本隔离与可终止性**：Windows 超时机制无法中断死循环，需子进程/子解释器隔离。单纯“超时后关闭会话”无法终止同进程 `exec`，必须保证可被强制杀掉的执行体。
*   **工件清理策略安全性**：`releases_only` 未实现应禁用或显式报错。

### P1
*   **分支指针更新**：修复 manifest 更新路径或提供专用 API。
*   **build/commit 语义一致性**：明确 build 是否产出工件，保持文档一致。
*   **回滚缺失**：至少保证“失败时不污染历史/manifest”。

### P2
*   **溯源信息不足**：缺少依赖版本、配置快照等构建 provenance。
*   **Unique Solution 语义仍是空缺**：需要特征级约束声明。

## 5. 建议的文档修订点

*   修正 v2 实现总结中对 build 产物、回滚机制、releases_only 的描述。
*   明确测试结论来源（命令、报告、覆盖率文件）。
*   补充 Windows 超时限制的已知风险。

## 6. 结论

v2 的架构性目标已基本达成，但当前仍处于工程化“收口期”。建议先修正文档与实现的关键不一致，再集中处理脚本隔离与工件清理策略的安全性问题。
