## 核心改进

### 1. 模型包架构 (.456d)

**v1.0 问题**:
- `.cad/` 目录结构分散
- pickle 缓存在复杂模型上不稳定（>150面时失败）
- 无统一的包管理机制

**v2.0 方案**:
```
<model_name>.456d/
├── manifest.json          # 包元数据和配置
├── src/                   # 源代码
│   └── main.py
├── vcs/                   # 版本控制
│   └── commits.jsonl      # JSONL格式历史
├── artifacts/             # 构建工件
│   └── <commit_hash>/
│       ├── model.step     # STEP文件
│       ├── thumb_*.png    # 缩略图
│       ├── thumb_*.json   # 渲染元数据
│       ├── metrics.json   # 几何指标
│       └── validate.json  # 验证结果
└── runlog/                # 执行日志
```

**优势**:
- 自包含：所有文件在一个包内
- 可移植：整个目录可以复制/移动
- 结构清晰：职责明确的子目录

### 2. STEP 工件替代 Pickle

**v1.0 问题**:
- pickle 序列化在复杂几何体上失败
- 跨版本兼容性差
- 无法用外部工具打开

**v2.0 方案**:
- 使用 STEP (ISO 10303) 标准格式
- 通过 `build123d.export_step()` 导出
- 通过 `build123d.import_step()` 加载
- 可靠支持任意复杂度的模型

**实现**:
```python
# artifact.py
def save_step(self, shape: "Shape", commit_hash: str) -> Path:
    from build123d import export_step
    step_path = artifact_dir / "model.step"
    export_step(shape, str(step_path))
    return step_path

def load_step(self, commit_hash: str) -> Optional["Shape"]:
    from build123d import import_step
    shape = import_step(str(step_path))
    return shape
```

### 3. JSON 元数据输出

**v1.0 问题**:
- 渲染只输出 PNG，无相机参数
- 无法复现视角

**v2.0 方案**:
- 每个缩略图配套 JSON 文件
- 记录相机位置、焦点、上方向
- 记录分辨率和时间戳

**输出示例**:
```json
{
  "view": "iso",
  "camera": {
    "position": [126.68, -126.68, 126.68],
    "focal_point": [0.0, 0.0, 0.0],
    "view_up": [0.0, 0.0, 1.0]
  },
  "resolution": [800, 600],
  "timestamp": "2026-01-31T02:07:35.565936"
}
```

### 4. JSONL 提交历史

**v1.0 问题**:
- 每个提交一个 JSON 文件
- 读取历史需要遍历目录
- 性能较差

**v2.0 方案**:
- 单个 `commits.jsonl` 文件
- 追加写入，读取高效
- 支持流式处理

**格式示例**:
```jsonl
{"hash":"abc123","message":"Initial","timestamp":"2026-01-31T10:00:00","script_path":"src/main.py","branch":"main","has_step":true,"has_thumbnails":true}
{"hash":"def456","message":"Updated","timestamp":"2026-01-31T11:00:00","script_path":"src/main.py","branch":"main","has_step":true,"has_thumbnails":true}
```

### 5. 工件管理策略

**新增功能**:
- `cad artifacts list` - 查看工件占用
- `cad artifacts clean` - 按策略清理

**清理策略**:
- `all_commits` - 保留所有
- `latest_per_branch` - 仅保留分支头（默认）
- `releases_only` - 仅保留发布版本

## 技术实现细节

### 1. 包发现机制

支持从任意子目录查找包：

```python
@classmethod
def find_package(cls, start_path: Optional[Path] = None) -> Optional["ModelPackage"]:
    """向上遍历目录树，查找 .456d 包"""
    current = start_path.resolve()
    while current != current.parent:
        if str(current).endswith(cls.PACKAGE_EXTENSION):
            if (current / "manifest.json").exists():
                return cls(current)
        # 检查子目录
        for child in current.iterdir():
            if child.is_dir() and str(child).endswith(cls.PACKAGE_EXTENSION):
                if (child / "manifest.json").exists():
                    return cls(child)
        current = current.parent
    return None
```

### 2. 构建工作流

完整的构建流程：

```
执行脚本 → 验证几何 → 保存STEP → 渲染缩略图 → 保存指标 → 更新历史 → 更新manifest
```

实现为 `BuildWorkflow` 类，支持：
- 单独构建（不提交）
- 提交时自动构建
- 错误处理和回滚

### 3. 错误处理改进

统一的错误信息格式：

```python
@dataclass
class ErrorInfo:
    file: str
    line: int
    type: str
    code: ErrorCode  # E-SYNTAX, E-RUNTIME, E-BREP, E-IO
    message: str
    hint: Optional[str] = None
```

支持 ErrorCode 枚举和字符串的兼容：

```python
def to_dict(self) -> dict[str, Any]:
    return {
        "code": self.code.value if isinstance(self.code, ErrorCode) else self.code,
        ...
    }
```

### 4. 渲染增强

支持多视图并行渲染：

```python
render_views = ["top", "front", "right", "iso"]
for view_name in render_views:
    metadata = renderer.render(
        shape,
        STANDARD_VIEWS[view_name],
        output_png,
        output_json
    )
```

每个视图生成：
- PNG 图像
- JSON 元数据（相机参数）

## 遇到的问题与解决

### 1. build123d API 变化

**问题**: `shape.export_step()` 方法不存在

**解决**: 使用模块级函数 `export_step(shape, path)`

```python
# ❌ 错误
shape.export_step(str(step_path))

# ✅ 正确
from build123d import export_step
export_step(shape, str(step_path))
```

### 2. ErrorCode 序列化

**问题**: `ErrorCode.value` 在字符串类型的 code 上失败

**解决**: 类型检查

```python
"code": self.code.value if isinstance(self.code, ErrorCode) else self.code
```

### 3. import_step 返回值

**问题**: 不确定返回单个shape还是列表

**解决**: 实测验证，直接返回 Shape 对象

```python
shape = import_step(str(step_path))  # 直接返回Shape
return shape
```

### 4. 测试冲突

**问题**: v1 和 v2 测试文件名冲突

**解决**: 删除 v1 测试目录，仅保留 v2 测试

## 性能对比

### STEP vs Pickle

| 指标 | Pickle (v1) | STEP (v2) |
|------|-------------|-----------|
| 简单模型 (6面) | 1-2 KB | 15 KB |
| 复杂模型 (>150面) | ❌ 失败 | ✅ 可靠 |
| 加载速度 | 快 (~0.1s) | 中等 (~1.5s) |
| 跨版本兼容 | ❌ 差 | ✅ 好 |
| 外部工具支持 | ❌ 无 | ✅ 标准格式 |

**结论**: STEP 虽然文件较大、加载稍慢，但可靠性和兼容性显著优于 pickle。

### 提交历史

| 指标 | JSON文件 (v1) | JSONL (v2) |
|------|---------------|-----------|
| 存储方式 | 每提交一个文件 | 单个追加文件 |
| 读取速度 (100提交) | 需遍历100个文件 | 读取单个文件 |
| 写入速度 | 创建新文件 | 追加写入 |
| 文件系统压力 | 高 | 低 |

**结论**: JSONL 在大量提交时性能更优。
